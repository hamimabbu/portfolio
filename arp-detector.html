ARP poisoning detector

A small Python tool that watches ARP traffic and raises an alert when one MAC address claims several IPs, or one IP is claimed by several MACs.

Project
Group assignment for System Security (CSCI262), six members, Oct 2025. My copy has been tidied and extended since.
Stack
Python, Scapy. Lab work with Kali Linux, Metasploitable and Wireshark.
Status
Tested. 14 unit tests pass on Windows and Linux with Python 3.11, 3.12 and 3.13 in GitHub Actions. The demo capture raises 3 alerts.
Code
github.com/hamimabbu/arp-poisoning-detector. Public.

01 / problem

Why ARP can be lied to

ARP is how a machine on a local network finds the MAC address that belongs to an IP address. Replies are not authenticated, so any machine on the network can send a forged reply and claim to be someone else. With the right forged replies, an attacker can sit between a victim and the router and read or change their traffic. This is a man-in-the-middle attack, listed in MITRE ATT&CK as T1557.002, ARP cache poisoning.

The victim has no built-in way to notice. In the group lab we ran ARP spoofing from Kali Linux against a Metasploitable machine and used Wireshark to look at the forged packets. Then we wrote a tool that spots them.

02 / how it works

Four steps

  1. Sniff

    Scapy captures packets from a live interface, or reads them from a saved pcap file.

  2. Filter

    Only ARP requests and replies are kept. Everything else is ignored, and so are probes with the source address 0.0.0.0.

  3. Remember

    Two tables in memory: which MACs have claimed each IP, and which IPs each MAC has claimed.

  4. Compare

    An IP with more than one MAC, or a MAC with more than one IP, raises an alert. Each alert is logged once.

Rule 1: one IP, two MACs

Two different machines say they own the same address. In an attack this happens when the attacker answers for the router or for the victim.

Rule 2: one MAC, two IPs

One machine says it owns several addresses. In a classic man-in-the-middle attack the attacker's MAC shows up for both the victim and the router.

03 / output

Real output

This is the detector reading the demo capture that comes with the project. One MAC (08:00:27:cc:cc:03) claims both 192.168.56.1 and 192.168.56.20, and each of those addresses already belongs to another MAC, so one attack raises three alerts.

The 14 unit tests cover normal traffic, both kinds of alert, repeated alerts, forged requests, ignored packets, the demo capture, log output and error handling.

04 / defences

Defences we compared

Detecting an attack is not the same as stopping it. For the assignment we wrote up the trade-offs of three ways to defend against ARP poisoning.

Static ARP
Fixed IP-to-MAC entries that forged replies cannot overwrite. Simple and effective on a few machines, but kept up by hand, so it does not scale.
Dynamic ARP Inspection
A managed switch checks every ARP packet against a trusted table built by DHCP snooping, and drops the ones that do not match. Works well at scale, but needs switches that support it.
Secure ARP
A proposed replacement that signs ARP messages. It closes the hole in the protocol itself, but needs keys and changes on every host, which is why it is rarely used.

05 / limits

What it does not do

Honest limits

  • It only detects. It does not block or repair anything.
  • It only sees the ARP traffic that reaches the machine it runs on.
  • Devices with several IP addresses, and failover setups, can cause false alarms.
  • If it starts after an attack has begun, it may learn the attacker's MAC as the real one.
  • It handles IPv4 ARP only. Its tables live in memory and reset when it restarts.
  • MITRE ATT&CK suggests watching for several IPs resolving to one MAC, and for unsolicited or repeated gratuitous ARP. This tool covers the first idea. It does not look for repeated gratuitous ARP.

Where it came from

This began as a six-member group assignment for System Security (CSCI262) in October 2025. The version in my repository is a cleaned-up copy with a capture-file mode, a log option, a demo capture and unit tests. The repository is public.
