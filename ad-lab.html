01 / network

What is in the lab

Everything runs in VirtualBox on its own internal network, separate from my everyday computers.

  • Domain controller with Active Directory Domain Services, DNS and Certificate Services (AD CS).
  • A Windows 11 client joined to the domain, with static IP addresses on both machines.
  • Users, an SMB file share, Group Policy and a service account with an SPN, which is what Kerberoasting needs.

02 / attacks

The three attacks I will run first

They are the usual first steps against a Windows domain, and each one leaves something a defender can look for. The "look for" lines are what I expect to find. I will confirm them in the lab before I treat them as results.

LLMNR and NBT-NS poisoning

planned ATT&CK T1557.001

If a Windows machine cannot find a name through DNS, it may ask the whole local network instead (LLMNR on UDP 5355, NBT-NS on UDP 137, mDNS on UDP 5353). An attacker can answer first and collect the authentication that follows.

Look for: name queries that DNS did not answer, followed by a reply from a machine that is not a DNS server. Unusual traffic on those three ports.

Defence: turn off LLMNR, mDNS and NetBIOS name resolution where they are not needed.

SMB relay

planned ATT&CK T1557.001

Instead of cracking the captured authentication, the attacker relays it to another machine and acts as the user there. It only works against machines that do not require SMB signing. The lab needs a second client for this, which is on my list.

Look for: the same account logging on from an address that does not belong to that user, right after a poisoning event.

Defence: require SMB signing, and segment the network.

Kerberoasting

planned ATT&CK T1558.003

Any domain user can ask for a Kerberos service ticket for an account that has an SPN. Part of that ticket is encrypted with the account's password, so it can be cracked offline. The lab already has a service account with an SPN for this.

Look for: Windows Event ID 4769 (a service ticket was requested) with RC4 encryption (type 0x17), and one account asking for many service tickets in a short time.

Defence: long random passwords on service accounts, and no RC4 where it is not needed.
