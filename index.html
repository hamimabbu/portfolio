CASE 01
Team capstone

OKR tracking module: secure evidence upload

Mar 2026 to present. Relevant to: application security, backend developer

Problem
A dashboard that accepts uploaded files is an easy way to bring a malicious file into a company. The OKR (objectives and key results) module lets people attach evidence to key results, so every upload had to be checked.
What I did
  • Built a scanner that checks file signatures and inspects PDFs, ZIP archives, images and documents for threats.
  • Added upload rate limiting, an audit page for blocked files and real-time alerts with Socket.IO.
  • Added a review step: a manager can allow some blocked files once. Other blocks are final.
  • Built role-based permissions for groups and managers on the backend.
Result
Uploads are checked before they are accepted, and blocked files show up on an audit page. Covered by backend integration tests and Cypress end-to-end tests. 30+ commits of my own in the team repository.
  • File upload security
  • Node.js

  • MongoDB
  • Socket.IO

CASE 02
Tested

ARP poisoning detector

Oct 2025. Relevant to: SOC analyst, network security

Problem
ARP has no authentication, so any machine on a network can claim to be any other. The victim has no built-in way to notice.
What I did
  • Started as a six-person System Security (CSCI262) assignment. We ran ARP spoofing from Kali against Metasploitable and inspected the forged packets in Wireshark.
  • The tool uses Scapy to watch ARP traffic. It alerts when one MAC address claims several IPs, or one IP is claimed by several MACs.
  • My copy reads live traffic or a saved capture file, can write a log, and comes with a demo capture and unit tests.
Result
14 unit tests pass on Windows and Linux with Python 3.11, 3.12 and 3.13 in GitHub Actions, and the demo capture raises 3 alerts.
  • Python
  • Scapy
  • Wireshark
  • Kali Linux
  • Network security

CASE 04
Tested

LayerLens: what a browser and a connection reveal

Nov 2026. Independent project. Relevant to: application security, backend developer

Problem
A website can read many details about a visitor's browser and connection, and they are easy to over-read. A tool that shows them back and looks things up about the visitor is easy to misuse, for example as a way to probe other networks.
What it does
  • Shows a visitor what their browser and connection reveal, with the source, the time and the limits of every result.
  • Looks up reverse DNS, registry and InternetDB records only after the operator switches a source on and the visitor approves it. The server works out the address itself, so a request cannot name a target, and local and reserved addresses never leave the server.
  • Limits request size, content type and calls per visitor, shows server text as plain text only, and keeps results in the tab with no database, cookies or analytics.
Result
62 automated tests pass on Node.js 22 and 24 in GitHub Actions. A written threat model lists nine risks with the control for each. It is not deployed, and the optional TLS fingerprint diagnostic has not been run against real TLS traffic.
  • Application security
  • Node.js
  • JavaScript
  • Docker
  • GitHub Actions
